# Network Automation Tool v3.0

A Python-based network automation learning project demonstrating device inventory validation, simulated Cisco IOS-style command execution, result collection, and automated report generation.

Developed as part of my journey in Telecommunications Engineering, Python programming, computer networking, and network automation.

**Current mode:** Simulation only. This version does not connect to live routers or switches.

## Features

* **Device inventory:** Maintains a list of routers and switches with names, device types, IPv4 addresses, and statuses.
* **Inventory validation:** Checks required fields, duplicate device names, IPv4 addresses, and supported status values.
* **Simulated command execution:** Demonstrates selected Cisco IOS-style commands.
* **Device-specific interface output:** Provides separate simulated interface information for R1, S1, R2, and R3.
* **Result collection:** Organizes command results by device.
* **Automated reporting:** Generates a timestamped `network_report.txt` file.
* **Error handling:** Reports inventory validation failures and file-writing errors.
* **Summary statistics:** Displays total, online, and offline device counts.

## Technologies

* Python 3
* `datetime` for timestamps
* `ipaddress` for IP address validation
* Lists, dictionaries, sets, and functions
* Loops, conditionals, and exception handling
* File handling

No third-party Python packages are required by the current implementation.

## Requirements

* Python 3 installed.
* VS Code or another code editor.
* A terminal or command prompt.

## How to Run

Open a terminal in the project directory and execute:

```bash
python network_automation_v3.py
```

On Windows, you can also try:

```bash
py network_automation_v3.py
```

The program validates its inventory, displays the devices, processes simulated commands, generates a report, and displays a summary.

## Commands Demonstrated

* `show ip interface brief`
* `show ip ssh`
* `show version`

These commands are simulated by Python. They are not sent to physical or virtual network devices.

## Validation and Testing

The v3.0 implementation has been checked for:

* Successful Python compilation.
* Acceptance of the default device inventory.
* Rejection of an invalid IPv4 address.
* Successful program execution and report generation.
* Clear identification of simulation mode in the report.

These checks are development tests, not proof of live-device connectivity.

## Simulation Limitations

* Device status is configured in the Python inventory.
* Command output is generated by the program.
* No SSH sessions are established.
* No live router or switch configuration is read or changed.
* Report contents reflect simulated data.
